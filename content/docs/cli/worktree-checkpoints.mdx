---
title: "Контрольные точки worktree"
description: "Краткие комментарии о состоянии работы, которые агенты обновляют через CLI."
---


У каждого worktree Orca есть текстовое поле **Комментарий**, видимое в интерфейсе. Это краткий снимок текущего состояния работы. Агенты могут обновлять его через CLI, чтобы держать коллег в курсе без обязательного общения в чате.

Основная команда
----------------

```
orca worktree set --worktree active --comment "reproduced auth failure; testing credential-chain fix" --json
```

Когда стоит оставлять контрольную точку
--------------------------------------

* Завершена значимая часть реализации.
* Гипотеза подтверждена или опровергнута.
* Закончена проверка кода.
* Возникла блокировка: ожидание внешних данных, ошибка в зависимости или отсутствие доступа.
* Работа переходит от исследования к исправлению или от исправления к проверке.

Формат
------

В первой строке укажите действие: что произошло, где и каково текущее состояние или следующий шаг.

```
orca worktree set --worktree active --comment "added debounce to SearchBar onChange (src/components/SearchBar.tsx); ready for review
goal: reduce redundant API calls per #298" --json
```

Чтение перед записью
--------------------

Если комментарий может содержать написанный пользователем контекст, сначала прочитайте его, чтобы не затереть цели и ограничения:

```
orca worktree current --json
```

Сохраните актуальную информацию, удалите устаревшую и добавьте своё обновление.

Проверка результата
-------------------

После записи снова выполните `orca worktree current --json` и убедитесь, что поле `comment` содержит актуальный статус. Комментарий должен помогать продолжить работу без чтения всей истории терминала: укажите подтверждённый результат, оставшийся риск и ближайший следующий шаг.

Не помещайте в контрольную точку токены, пароли, приватные URL и персональные данные. Комментарий виден другим участникам, имеющим доступ к рабочему пространству.
