Автоматизации Orca запускают запросы по расписанию из командной строки. Повторяющиеся задачи сортировки, проверки и обслуживания могут начинаться без ручного открытия worktree. Ниже вы создадите отключённую автоматизацию, проверите её и запустите, когда всё будет готово.

Создание первой безопасной автоматизации
----------------------------------------

Во время настройки запроса и цели используйте параметр `--disabled`:

```
orca automations create \
  --name "Weekday triage" \
  --trigger weekdays \
  --time 09:00 \
  --prompt "Triage new issues and summarize blockers" \
  --provider codex \
  --repo my-repo \
  --disabled \
  --json
```

Параметр `--trigger` принимает готовые значения `hourly`, `daily`, `weekdays` и `weekly`, а также выражения cron и строки RRULE. Если расписание должно учитывать определённый часовой пояс IANA, а не системный, укажите `--timezone <tz>`.

Выбор места запуска
-------------------

Используйте `--repo <селектор>`, если при каждом запуске нужно создавать или выбирать работу в репозитории. Параметр `--workspace <селектор>` запускает автоматизацию в существующем worktree Orca:

```
orca automations create \
  --name "Nightly status" \
  --trigger "0 18 * * 1-5" \
  --prompt "Summarize today's changes" \
  --provider claude \
  --workspace active \
  --disabled
```

Если оба параметра цели пропущены, Orca по возможности определяет окружающий worktree по текущему каталогу оболочки.

Повторное использование сессии
------------------------------

Для автоматизации в существующем worktree добавьте `--reuse-session`, если каждый следующий запуск должен продолжать работу в прежнем активном терминале, а не начинать новую сессию:

```
orca automations create \
  --name "Inbox digest" \
  --trigger hourly \
  --prompt "Summarize unread mail" \
  --provider codex \
  --workspace active \
  --reuse-session \
  --disabled
```

Команда `orca automations edit <automationId> --fresh-session --json` вернёт создание нового терминала при каждом запуске.

Проверка и включение
--------------------

Перед включением просмотрите список и параметры автоматизаций:

```
orca automations list --json
orca automations show <automationId> --json
orca automations edit <automationId> --enabled --json
```

Команда `edit` меняет название, запрос, провайдера, цель, расписание и состояние. Команда `remove` удаляет автоматизацию вместе с историей запусков.

Ручной запуск
-------------

После создания запустите автоматизацию вручную, чтобы проверить запрос и цель до следующего события расписания:

```
orca automations run <automationId> --json
orca automations runs --id <automationId> --json
```

Если запуск завершился ошибкой до открытия рабочего пространства или повторного подключения к цели, откройте его в Orca и нажмите **Запустить снова**. Для той же автоматизации будет поставлен в очередь новый ручной запуск.
