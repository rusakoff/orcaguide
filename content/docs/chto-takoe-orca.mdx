---
title: "Что такое Orca?"
description: "Кому подходит Orca и в каких случаях она полезна: объяснение за минуту."
---

Orca представляет собой настольную среду разработки для одновременного запуска нескольких ИИ-агентов. Каждая задача получает отдельный git worktree, терминал агента и вкладку браузера. Claude Code, Codex, Cursor CLI и другие агенты работают параллельно и не перезаписывают файлы друг друга. Разработчику не приходится постоянно убирать изменения в stash и переключать ветки в одной рабочей копии.

![Главное окно Orca: список worktree на боковой панели, терминалы агентов и просмотр изменений в разделённых областях](https://www.onorca.dev/whats-new/posters/orca-split-screen.jpg)

Когда Orca подходит
-------------------

* Вы хотите поручить трём агентам параллельно исправлять одну и ту же ошибку, а затем выбрать лучший результат.
* Вы хотите внимательно проверять созданные ИИ изменения перед отправкой в проект.
* Вы уже оплачиваете Claude Code, Codex или Cursor CLI и хотите управлять ими из одного места.
* Вы хотите запускать агентов удалённо: по SSH, на собственном сервере Orca или в виртуальной машине по запросу, сохраняя привычную среду разработки.

Для кого предназначена Orca
---------------------------

Orca рассчитана на разработчиков, которые используют ИИ как дополнительный инструмент, а не как замену работе с кодом. Здесь нужно читать diff, проверять коммиты и следить за состоянием worktree. Для разработки без кода Orca не подходит.

Чем Orca не является
--------------------

* Orca не является моделью. Она запускает агентов, которыми вы уже пользуетесь. Подключите свою подписку на Claude, Codex или OpenCode.
* Orca не заменяет Git. Каждый worktree остаётся обычным git worktree. В него можно перейти командой `cd` и продолжить работу из терминала.
* Orca не предоставляет облачный VPS. По умолчанию она работает на вашем компьютере. Для удалённых вычислений нужны машины и облачные учётные записи под вашим управлением: [SSH-подключения](/docs/reference/ssh), [собственные серверы Orca](/docs/reference/remote-servers) или [отдельные среды для рабочих пространств](/docs/reference/ways-to-run#4-per-workspace-environments-ephemeral-vms).
