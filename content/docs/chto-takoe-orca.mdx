Кому подходит Orca и в каких случаях она полезна: объяснение за минуту.

Orca работает как настольная среда разработки, в которой можно одновременно запускать нескольких ИИ-агентов для программирования. Каждая задача получает отдельный git worktree, терминал агента и вкладку браузера. Благодаря этому вы можете распределять работу между Claude Code, Codex, Cursor CLI и другими агентами, не откладывая изменения в stash, не переключаясь постоянно между ветками и не теряя рабочий контекст.

Когда стоит использовать Orca
-----------------------------

* Вы хотите поручить трём агентам параллельно исправлять одну и ту же ошибку, а затем выбрать лучший результат.
* Вы хотите внимательно проверять созданные ИИ изменения перед отправкой в проект.
* Вы уже оплачиваете Claude Code, Codex или Cursor CLI и хотите управлять ими из одного места.
* Вы хотите запускать агентов удалённо: по SSH, на собственном сервере Orca или в виртуальной машине по запросу, сохраняя привычную среду разработки.

Для кого предназначена Orca
---------------------------

Orca создана для тех, кто профессионально пишет код и хочет использовать ИИ как дополнительный инструмент, а не как замену разработчику. Предполагается, что вы читаете diff, внимательно относитесь к коммитам и поддерживаете порядок в worktree. Если вам нужен инструмент для разработки без кода, Orca вам не подойдёт.

Чем Orca не является
--------------------

* **Это не модель.** Orca запускает агентов, которыми вы уже пользуетесь. Подключите свою подписку на Claude, Codex или OpenCode.
* **Это не замена Git.** Каждый worktree в Orca является обычным git worktree. Вы в любой момент можете перейти в него командой `cd` и работать с Git из терминала.
* **Это не облачный VPS-сервис.** По умолчанию Orca работает на вашем компьютере. Для удалённых вычислений используются машины и облачные учётные записи под вашим управлением: [SSH-подключения](/docs/reference/ssh), [собственные серверы Orca](/docs/reference/remote-servers) или [отдельные среды для рабочих пространств](/docs/reference/ways-to-run#4-per-workspace-environments-ephemeral-vms).
