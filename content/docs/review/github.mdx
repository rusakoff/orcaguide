Orca связывает worktree с pull request или merge request и показывает состояние внешней проверки. Задачи GitHub и GitLab также доступны внутри приложения.

![Интеграция GitHub: pull request, проверки и задачи внутри worktree](https://www.onorca.dev/whats-new/posters/orca-github.jpg)

Подключение провайдера
----------------------

Подключите провайдера репозитория в разделе [Настройки → Интеграции](/docs/reference/settings). Для GitHub глубже всего поддерживаются Actions и задачи. Merge request и задачи GitLab используют тот же процесс проверки. Pull request Bitbucket, Azure DevOps и Gitea отображаются на боковой панели worktree и панели проверок. Перед отправкой ветки Orca проверяет конфликты с удалённой системой.

Проверки кода
-------------

* После отправки worktree создайте проверку из панели управления версиями и подтвердите базовую ветку, название, описание и статус черновика.
* Связанные проверки показываются на боковой панели с состоянием открыто, слито или закрыто.
* В строке ветки доступна ссылка **Открыть страницу проверки в браузере**, если известен URL pull request или merge request.
* Для GitHub в меню pull request можно скопировать ссылку, закрыть проверку или снова открыть её после подтверждения.
* Проверки GitHub, отзывы и комментарии открываются на вкладке pull request. Merge request и задачи GitLab используют тот же интерфейс.
* На панели проверок можно отвечать на любой комментарий обсуждения.
* При неудачных проверках GitHub действие **Исправить неудачные проверки** передаёт агенту названия и ссылки.

### Автоматическое слияние

Для открытого pull request GitHub кнопка слияния предлагает **Включить автоматическое слияние**. GitHub сольёт ветку после выполнения требований, включая проверки и обязательные отзывы. Метод берётся из настроек репозитория: squash, merge commit или rebase. Запрещённые методы не показываются. Действие **Отключить автоматическое слияние** отменяет ожидание. Если базовая ветка использует очередь слияния GitHub, кнопка называется **Слить, когда будет готово** и добавляет pull request в очередь. Автоматическое слияние скрыто для черновиков, закрытых, конфликтующих и нестабильных pull request, а также репозиториев без этой функции.

Задачи
------

На панели задач можно просматривать, фильтровать и изменять задачи GitHub и GitLab. При создании worktree из задачи название заполняется автоматически, а связь сохраняется для проверки.

В карточке задачи GitHub раздел **Активность** объединяет комментарии с событиями: назначениями, упоминаниями, перекрёстными ссылками, сменой состояния и перемещением по проекту.

Ссылку на связанную задачу можно скопировать из меню worktree. Для GitLab список показывает открытые задачи выбранного проекта и умеет фильтровать назначенные вам.

Actions
-------

Неудачные проверки GitHub Actions отображаются красным индикатором. Нажмите его, чтобы открыть журналы задания внутри Orca.

Проекты
-------

Раздел **Задачи** содержит представление GitHub Projects: карточки из разных репозиториев, фильтр по исходному репозиторию, состояния черновых pull request и создание worktree из карточки.

Устранение неполадок
--------------------

Если состояния pull request, проверки или проекты не обновляются из-за лимитов, авторизации `gh`, разрешений или сети, прочитайте статью [Ошибки GitHub](/docs/reference/github-errors).
