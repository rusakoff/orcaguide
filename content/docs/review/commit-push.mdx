---
title: "Коммит и отправка из Orca"
description: "Добавление изменений в индекс, создание коммита, отправка ветки и открытие проверки."
---

Панель рядом с просмотром diff добавляет изменения в индекс, создаёт коммит и отправляет ветку. После отправки из неё же можно открыть проверку кода.

Создание коммита
----------------

1. Добавьте изменения в индекс по фрагментам или файлам.
2. Напишите сообщение в нижней панели либо нажмите **Создать с помощью ИИ**, чтобы Orca подготовила его по изменениям в индексе.
3. Нажмите **Коммит** или `Cmd-Enter`.

Хуки pre-commit репозитория выполняются как обычно. При ошибке Orca показывает их вывод на месте.

В подробностях неудачного коммита доступно действие **Исправить с помощью ИИ**. Оно запускает стандартного агента активного worktree и передаёт ему вывод хука, сообщение коммита и список файлов в индексе. Агент получает только запрос на исправление. Он не должен обходить хуки, создавать коммит, отправлять ветку или открывать проверку.

Отправка ветки
--------------

Кнопка **Отправить** публикует ветку worktree в `origin` и при первом запуске задаёт upstream. Если локальная ветка отстаёт, Orca не выполняет принудительную отправку без предупреждения.

После изменения истории через rebase, amend или squash панель показывает отдельное действие **Принудительно отправить с lease**. Оно не используется как запасной вариант обычной отправки. Подпись указывает число заменяемых коммитов и upstream-ветку. Команда применяет `--force-with-lease`, поэтому при устаревших локальных данных об удалённой ветке отправка завершится ошибкой, а чужие коммиты не будут затёрты.

Открытие проверки
-----------------

После отправки ветки создайте pull request или merge request через панель управления версиями. Перед подтверждением проверьте базовую ветку, название, описание и статус черновика.

Если во время создания pull request Orca должна выполнить дополнительный коммит, но хуки отклоняют его или рабочее дерево находится в неподходящем состоянии, окно показывает подробную ошибку и дальнейшие действия. Передайте её агенту через **Исправить с помощью ИИ** или устраните самостоятельно и повторите попытку.

Кнопка **Создать описание pull request с помощью ИИ** заполняет базовую ветку, название, описание и статус черновика по diff и коммитам. Проверьте поля перед созданием.

Рецепты действий ИИ для репозитория
-----------------------------------

Действия **Создать с помощью ИИ**, **Создать описание pull request с помощью ИИ**, **Исправить с помощью ИИ** и **Разрешить с помощью ИИ** используют рецепты. Рецепт задаёт агента, аргументы CLI и шаблон запроса. Их можно менять в разделе [Настройки → Git и управление версиями](/docs/reference/settings) → **Рецепты действий** глобально или для текущего репозитория.

Переопределение репозитория не меняется при сохранении глобального рецепта. В настройках отображается список отличающихся репозиториев и переопределённых параметров с кнопкой перехода.

Изменение последнего коммита
----------------------------

Amend запускается явно через **Коммит → Изменить последний коммит**. Для уже отправленного коммита Orca запросит подтверждение.

Панель управления версиями
---------------------------

На боковой панели **Управление версиями** доступны те же действия: добавление и отмена изменений, сообщение коммита, **Коммит**, **Отправить**, **Получить** и **Синхронизировать**. Пути отображаются в UTF-8, включая символы вне ASCII.

Основная нижняя кнопка меняется по состоянию: **Добавить файлы**, затем **Коммит**, после чего **Отправить**, **Получить** или **Синхронизировать** в зависимости от отношения ветки к upstream.

При конфликтах merge, rebase, cherry-pick или revert рядом с **Проверить конфликты** появляется **Разрешить с помощью ИИ**. Можно передать конфликт агенту или изучить самостоятельно. Ненужный merge или rebase отменяется действиями **Прервать merge** и **Прервать rebase**.
