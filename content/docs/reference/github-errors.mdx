Orca обращается к GitHub через установленный на локальном или удалённом компьютере **GitHub CLI (`gh`)**. Если pull request, проверки, задачи или управление версиями не обновляются, причиной обычно является авторизация, разрешения или лимит API.

Быстрая диагностика
-------------------

Сообщение

Вероятная причина

Первое действие

**GitHub ограничивает запросы** или `rate limit exceeded (core)`

Исчерпан лимит REST

Дождитесь сброса, остановите лишние вызовы `gh` и проверьте **Настройки → Git → Бюджет GitHub API**

**Авторизация GitHub недоступна**

Вход не выполнен, токен истёк или неверен `GITHUB_TOKEN`

Выполните `gh auth status`, затем `gh auth login`

**GitHub запретил доступ**, HTTP 403 без лимита

Не хватает областей токена или доступа к репозиторию

Повторно войдите с областью `repo`, подтвердите SSO

**Репозиторий недоступен**, HTTP 404

Неверный remote, переименованный или закрытый репозиторий

Проверьте `git remote -v` и доступ в браузере

**GitHub недоступен**, тайм-аут

Сеть, прокси, VPN или сбой GitHub

Проверьте [GitHub Status](https://www.githubstatus.com/) и соединение без VPN

**GitHub CLI недоступен**

`gh` отсутствует в `PATH`

Установите `gh` и перезапустите Orca

Лимиты запросов
---------------

У авторизованного пользователя общий почасовой бюджет для Orca, терминальных команд `gh`, агентов, CI, расширений и других приложений.

Основные корзины:

* **REST (core):** большинство запросов pull request и задач, обычно 5000 в час.
* **GraphQL:** проекты и сложные запросы, обычно 5000 баллов в час.
* **Search:** списки на основе поиска, обычно 30 запросов в минуту.

После HTTP 403 с `API rate limit exceeded` Orca сохраняет последнее известное состояние и временно прекращает новые вызовы `gh`, чтобы не создавать поток ошибок.

### Почему бюджет в настройках может выглядеть нормальным

Панель бюджета использует специальный endpoint `rate_limit`, который сам не расходует лимит и иногда показывает остаток, хотя обычные REST-запросы уже получают ноль. При расхождении доверяйте в таком порядке:

1. ошибке на панели pull request или проверок;
2. настоящему запросу `gh`;
3. диагностическим значениям настроек.

Лимит GitHub API не связан с лимитами Claude, Codex и Grok.

### Проверка в терминале

```
# Диагностический запрос, не расходующий лимит
gh api rate_limit --jq '.resources | {core, graphql, search}'

# Настоящий REST-запрос
gh api user -i 2>&1 | head -40
```

HTTP 403, `API rate limit exceeded` и `X-Ratelimit-Remaining: 0` означают блокировку REST до времени `X-Ratelimit-Reset`.

Лимит часто расходуют несколько окон Orca, автоматические вызовы `gh` агентами, массовая работа с проектами и другие приложения с тем же токеном.

Дождитесь сброса, закройте лишние экземпляры Orca, приостановите автоматизации и не обновляйте панель вручную. В сценариях объединяйте GraphQL-запросы вместо отдельного REST-вызова для каждого pull request.

Проблемы авторизации
--------------------

```
gh auth status -h github.com
gh api user --jq '{login, id}'
```

Рабочая конфигурация показывает активный вход и возвращает пользователя.

Переменные `GITHUB_TOKEN` и `GH_TOKEN` имеют приоритет над связкой ключей. Устаревшее значение в профиле оболочки вызывает ошибки:

```
unset GITHUB_TOKEN GH_TOKEN
gh auth logout -h github.com
gh auth login -h github.com
```

Истёкший токен обновляется через `gh auth login` или `gh auth refresh`, после чего Orca нужно перезапустить. Для закрытых репозиториев организации может потребоваться SAML SSO.

Авторизация действует отдельно на каждом компьютере. Для удалённого worktree войдите через `gh auth login` на самом сервере.

Разрешения и репозитории
------------------------

HTTP 403 без сообщения о лимите означает недостаточные разрешения. HTTP 404 может скрывать недоступный закрытый репозиторий. Проверьте, что ресурс открывается в браузере от пользователя `gh api user`, и повторите вход с `repo`, а при необходимости `read:org` или `project`. Для GitHub Enterprise укажите hostname.

Сеть и сбои GitHub
------------------

При тайм-аутах и ошибках DNS проверьте GitHub Status, отключите VPN или корпоративный прокси и убедитесь, что удалённый сервер имеет HTTPS-доступ к `api.github.com`.

Отсутствует GitHub CLI
----------------------

Установите [`gh`](https://cli.github.com/), проверьте `which gh` и полностью перезапустите Orca. В Windows устанавливайте CLI в ту среду, которую использует Orca: нативную или WSL.

Поведение Orca при ошибке
-------------------------

При лимите или сбое Orca сохраняет последнее известное состояние и показывает предупреждение. Жёсткая ошибка авторизации или доступа выводит отдельное сообщение. После 403 автоматический предохранитель временно блокирует новые процессы `gh` для соответствующей корзины.

Если проблема сохраняется
-------------------------

1. Повторите сбой командой `gh pr view` или `gh api user` на том же компьютере.
2. Откройте журналы через **Справка → Открыть журналы**.
3. Создайте отчёт с текстом ошибки без секретов, очищенным выводом `gh auth status` и результатом терминальной проверки.
